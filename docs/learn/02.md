# 02 · MFA Fatigue

An employee receives repeated, unexpected sign-in approval prompts. Inspect identity logs and decide when repeated denials deserve investigation.

**Track** Beginner · 8 min · Identity

**Prerequisites** Read the baseline and compare event fields. No external tools are required.

## Investigate

**Attacker intent** Repeated approval prompts.

**Learning outcome** Confirm the user, method and outcome. Three distinct challenge IDs within five minutes link the alert to individual requests.

1. Review the clean baseline. Entra sign-in or audit projection supplies the exercise evidence.
2. Consider the hypothesis. Three distinct denied push prompts for one user within five minutes warrant investigation.
3. Replay the positive fixture and inspect THX-02. Confirm the user, method and outcome. Three distinct challenge IDs within five minutes link the alert to individual requests.
4. Compare the noisy fixture. Someone re-enrolling a phone can deny repeated prompts. An approved enrollment test is recorded with a change context.

## Rule and evidence

Count at least 3 observation(s) per `user` inside 300 seconds. Count distinct `observables.challenge_id` values.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"mfa_challenge"` |
| `outcome` | `eq` | `"denied"` |
| `observables.auth_method` | `eq` | `"push"` |

Review the following event-level exclusions before changing the rule.

- `observables.change_context` eq `"approved_enrollment"`

Tuning guidance. Check user impact and enrollment history. Set thresholds from known login behavior and review any training-account exceptions.

## Contain and prevent

Contact the user through a trusted channel. If a prompt was unexpectedly approved, revoke sessions and review subsequent sign-ins.

Require phishing-resistant MFA where possible. Enable number matching and authentication throttling for remaining push users.

## Knowledge check

- What makes these prompt denials one alert?
  - Three distinct pushes for one user in five minutes
  - Three prompts anywhere in the tenant
  - A single denied sign-in

<details>
<summary>Answer and rationale</summary>

Three distinct pushes for one user in five minutes. The rule groups by user and counts distinct challenge IDs within a five-minute window.

</details>

- What should you verify with the user?
  - Whether the account uses a long display name
  - Whether the prompts were expected or approved
  - Whether the portal was slow

<details>
<summary>Answer and rationale</summary>

Whether the prompts were expected or approved. Unexpected prompts can indicate attempted access. Approval changes the response priority.

</details>
