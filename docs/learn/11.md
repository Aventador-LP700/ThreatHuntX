# 11 · Token Theft

Investigate synthetic use of one application session fingerprint from different context and risk signals.

**Track** Advanced · 15 min · Identity

**Prerequisites** Know the basics of Identity auditing and how to review authorization context.

## Investigate

**Attacker intent** Misuse captured sessions.

**Learning outcome** Compare session identifiers, network and device posture enrichments, then check data or control-plane actions.

1. Review the clean baseline. Entra sign-in or audit projection supplies the exercise evidence.
2. Consider the hypothesis. Successful application session use from an unmanaged context and a new ASN merits a pivot to the original sign-in.
3. Replay the positive fixture and inspect THX-11. Compare session identifiers, network and device posture enrichments, then check data or control-plane actions.
4. Compare the noisy fixture. A legitimate device replacement or roaming user may appear in a new context.

## Rule and evidence

Count at least 1 observation(s) per `user` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"token_use"` |
| `observables.session_context` | `eq` | `"new_asn_unmanaged"` |
| `observables.risk_level` | `eq` | `"high"` |

Tuning guidance. Combine ASN drift with device confidence and prior sign-in evidence. Avoid treating geography as a sole signal.

## Contain and prevent

Verify user activity out of band, revoke suspicious sessions and scope subsequent access.

Enforce phishing-resistant authentication, managed device policy and token binding where supported.

## Knowledge check

- What should link the records?
  - A common session reference
  - A matching timestamp alone

<details>
<summary>Answer and rationale</summary>

A common session reference. The session, actor and surrounding context support the pivot.

</details>

- Which response closes an active session?
  - Update the alert title
  - Revoke sessions using the identity provider

<details>
<summary>Answer and rationale</summary>

Revoke sessions using the identity provider. Session revocation addresses access already established.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

This lesson observes possible token reuse. The fingerprint is an inert label and identifies no real token.

Enterprise ATT&CK 20.1 · related. Observed reuse can be consistent with application token abuse. It does not establish how the token was obtained.
