# 22 · Cloud Exfiltration

Review repeated bulk reads of restricted cloud objects by a principal outside its usual workload.

**Track** Advanced · 15 min · Cloud

**Prerequisites** Know the basics of Cloud auditing and how to review authorization context.

## Investigate

**Attacker intent** Mass object access/exports.

**Learning outcome** Check the principal, data classification, object count and bucket. Compare workload history and transfer logs.

1. Review the clean baseline. Cloud audit projection supplies the exercise evidence.
2. Consider the hypothesis. Repeated high-volume GetObject activity on restricted data by one identity warrants verifying purpose and destination.
3. Replay the positive fixture and inspect THX-22. Check the principal, data classification, object count and bucket. Compare workload history and transfer logs.
4. Compare the noisy fixture. An approved backup, restore or analytics load can read numerous restricted objects.

## Rule and evidence

Count at least 2 observation(s) per `user` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"object_read_summary"` |
| `observables.operation` | `eq` | `"GetObject"` |
| `observables.data_class` | `eq` | `"restricted"` |
| `observables.objects_read` | `gte` | `200` |

Review the following event-level exclusions before changing the rule.

- `observables.job_context` eq `"approved_backup"`

Tuning guidance. Separate scheduled jobs by role and baseline expected data volume per role and bucket.

## Contain and prevent

Confirm scope and destination, preserve object access logs and restrict unauthorized sessions or roles.

Enable object-level audit for restricted storage, scope access and enforce approved destinations.

## Knowledge check

- What telemetry closes the destination question?
  - Transfer, egress or provider delivery records
  - A bucket display name

<details>
<summary>Answer and rationale</summary>

Transfer, egress or provider delivery records. Successful reads establish access. Subsequent transfer evidence clarifies export.

</details>

- What should be baselined together?
  - Only the time of day
  - Principal, bucket and volume

<details>
<summary>Answer and rationale</summary>

Principal, bucket and volume. Expected workload varies by bucket and role.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

The fixture contains read summaries. The records do not establish where data went after retrieval.

Enterprise ATT&CK 20.1 · related. T1530 describes collection from cloud storage. External transfer requires additional evidence.
