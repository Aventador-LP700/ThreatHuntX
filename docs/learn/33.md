# 33 · GitHub Actions tampering

Review a workflow file change that broadened job permissions without corresponding protection or review.

**Track** Intermediate · 12 min · CI/CD

**Prerequisites** Be comfortable reading timestamps and github organization audit projection fields.

## Investigate

1. Review the clean baseline. GitHub organization audit projection supplies the exercise evidence.
2. Consider the hypothesis. A workflow update that adds write permissions outside approved review warrants examining the diff and executed jobs.
3. Replay the positive fixture and inspect THX-33. Use the changed path, permissions delta and review status. Pivot to revision, branch rules and any resulting run.
4. Compare the noisy fixture. An emergency policy adjustment can add scoped write rights before normal release workflows run.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"repository_push"` |
| `observables.path` | `starts_with` | `".github/workflows/"` |
| `observables.permissions_delta` | `eq` | `"write_added"` |
| `observables.review_status` | `eq` | `"unreviewed"` |

Tuning guidance. Require independently recorded emergency approval and expiration. Inspect permissions by individual job.

## Contain and prevent

Preserve the diff, inspect runner and job logs, revert an unauthorized workflow change and scope token exposure.

Protect workflow paths with CODEOWNERS and required review. Set least-privilege and explicit workflow permissions.
