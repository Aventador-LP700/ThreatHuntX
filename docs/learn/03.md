# 03 · Password spraying

Look for repeated password failures across several different accounts from a common source.

**Track** Beginner · 8 min · Identity

**Prerequisites** Read the baseline and compare event fields. No external tools are required.

## Investigate

1. Review the clean baseline. Entra sign-in or audit projection supplies the exercise evidence.
2. Consider the hypothesis. Four distinct users with bad-password failures from one source within ten minutes warrant a password-spray hunt.
3. Replay the positive fixture and inspect THX-03. Group by source IP, count distinct usernames, and pivot to subsequent successful sign-ins.
4. Compare the noisy fixture. A shared proxy or SSO outage can make unrelated failures appear to have the same source.

## Rule and evidence

Count at least 4 observation(s) per `source_ip` inside 600 seconds. Count distinct `user` values.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"sign_in"` |
| `outcome` | `eq` | `"failure"` |
| `observables.failure_reason` | `eq` | `"bad_password"` |

Tuning guidance. Enrich by network ownership and client app. Compare against the usual mix of users behind a shared address.

## Contain and prevent

Check successful sign-ins for the targeted users, revoke suspicious sessions, and coordinate blocking with the identity team.

Use phishing-resistant MFA, adaptive access, smart lockout and monitored legacy protocol controls.

## Knowledge check

- What is counted for this alert?
  - Distinct users
  - Password length

<details>
<summary>Answer and rationale</summary>

Distinct users. Counting unique accounts prevents repeated typos by one user from dominating.

</details>

- What can produce similar activity?
  - A single renamed file
  - A shared proxy during an SSO problem

<details>
<summary>Answer and rationale</summary>

A shared proxy during an SSO problem. Many legitimate users can share one egress address.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

One IP represents a deterministic fixture. Distributed attacks require additional grouping or telemetry.

Enterprise ATT&CK 20.1 · direct. The behavior in this lesson corresponds to this technique; the fixture models a defensive observation.
