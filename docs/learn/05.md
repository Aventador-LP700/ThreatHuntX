# 05 · OAuth consent phishing

Review an OAuth consent audit event for an unverified publisher and durable mailbox access.

**Track** Intermediate · 12 min · Identity

**Prerequisites** Be comfortable reading timestamps and entra sign-in or audit projection fields.

## Investigate

1. Review the clean baseline. Entra sign-in or audit projection supplies the exercise evidence.
2. Consider the hypothesis. A grant to an unverified publisher with offline access warrants review for unauthorized delegated access.
3. Replay the positive fixture and inspect THX-05. Inspect application ID, granting actor, scope and publisher verification. Confirm whether the grant was approved.
4. Compare the noisy fixture. Internal development applications can have unverified publishers and planned offline access.

## Rule and evidence

Count at least 1 observation(s) per `user` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"consent_grant"` |
| `observables.publisher_verified` | `eq` | `false` |
| `observables.granted_scope` | `contains` | `"offline_access"` |

Tuning guidance. Join approved applications and reviewed scopes. Flag newly granted scopes even for previously trusted apps.

## Contain and prevent

Preserve consent evidence, remove the suspicious grant and review mailbox or API activity tied to the app.

Require administrator review for sensitive consent and audit privileged delegated scopes.

## Knowledge check

- What is the durable-access clue?
  - The offline_access scope
  - The order of the UI columns

<details>
<summary>Answer and rationale</summary>

The offline_access scope. Offline access can permit session continuation after initial consent, subject to the provider.

</details>

- What should be preserved before revocation?
  - An actual token value
  - App ID and the grant audit record

<details>
<summary>Answer and rationale</summary>

App ID and the grant audit record. An application identifier and audit record support scoping without retaining credentials.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

The grant can precede token abuse. The fixture contains no token value or evidence of data access.

Enterprise ATT&CK 20.1 · related. Risky consent may enable theft or misuse of application access tokens. A consent event alone does not demonstrate token theft.
