# 23 · Ransomware-Like Activity

Determine whether repeated rename observations resemble ransomware impact or an approved file operation.

**Track** Intermediate · 12 min · Windows

**Prerequisites** Be comfortable reading timestamps and windows security or sysmon projection fields.

## Investigate

**Attacker intent** Simulated bulk file changes.

**Learning outcome** Check distinct file identifiers, extension pattern, process lineage and the affected share. Confirm recoverability with backups.

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. Four distinct renames to one unexpected extension pattern on a shared document host in two minutes warrant rapid triage.
3. Replay the positive fixture and inspect THX-23. Check distinct file identifiers, extension pattern, process lineage and the affected share. Confirm recoverability with backups.
4. Compare the noisy fixture. Controlled migrations and testing can perform bulk renames on a mapped share.

## Rule and evidence

Count at least 4 observation(s) per `host` inside 120 seconds. Count distinct `observables.file_id` values.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"file_rename"` |
| `observables.directory_class` | `eq` | `"shared_documents"` |
| `observables.extension_pattern` | `eq` | `"unexpected_uniform"` |

Review the following event-level exclusions before changing the rule.

- `observables.job_context` eq `"approved_conversion"`

Tuning guidance. Allow narrowly scoped, scheduled conversions with an accountable owner. Alert on activity outside that window.

## Contain and prevent

Preserve timestamps and writer evidence, isolate confirmed affected systems and validate recoverable backups.

Use offline tested backups, application control, staged share permissions and fast endpoint isolation procedures.

## Knowledge check

- Which evidence supports the alert?
  - Four distinct file IDs with an unexpected uniform extension
  - The presence of a .tmp extension alone

<details>
<summary>Answer and rationale</summary>

Four distinct file IDs with an unexpected uniform extension. Distinct paths and clustered rename behavior create the signal.

</details>

- What should you confirm before recovery?
  - The writer process name looks short
  - Backups are recent, isolated and recoverable

<details>
<summary>Answer and rationale</summary>

Backups are recent, isolated and recoverable. Restoration planning depends on tested backups and affected scope.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

The fixture is inert. It contains only rename observations and does not create, modify or encrypt learner files.

Enterprise ATT&CK 20.1 · related. Mass renames can be consistent with encryption for impact. Rename evidence alone does not show that content was encrypted.
