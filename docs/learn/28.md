# 28 · Browser Cookie Theft

Investigate a sensitive browser session-store access by a non-browser process.

**Track** Intermediate · 12 min · Windows

**Prerequisites** Be comfortable reading timestamps and windows security or sysmon projection fields.

## Investigate

**Attacker intent** Hijack web sessions.

**Learning outcome** Identify caller, target classification and operation. Compare application session changes for the same user.

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. A non-browser process reading the session store without approval warrants checking file and identity telemetry.
3. Replay the positive fixture and inspect THX-28. Identify caller, target classification and operation. Compare application session changes for the same user.
4. Compare the noisy fixture. Authorized profile backup, migration or endpoint response tools can read the store.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |

Tuning guidance. Allow only reviewed, signed tooling with explicit purpose and bounded access.

## Contain and prevent

Preserve endpoint evidence, validate access scope and revoke sessions if there is evidence of unintended access.

Restrict process access, enforce session protections and monitor browser profile access.

## Knowledge check

- What matters besides the target?
  - The identity and authorization of the reader
  - The browser window width

<details>
<summary>Answer and rationale</summary>

The identity and authorization of the reader. The same store can be accessed legitimately by the browser.

</details>

- What reduces the risk of continued session misuse?
  - Removing a screenshot
  - Revoking the relevant sessions

<details>
<summary>Answer and rationale</summary>

Revoking the relevant sessions. Revocation terminates existing authorization where supported.

</details>
