# 32 · CI/CD token theft

Review a workflow token-use audit projection when privileged actions come from an unapproved runner pool.

**Track** Advanced · 15 min · CI/CD

**Prerequisites** Know the basics of CI/CD auditing and how to review authorization context.

## Investigate

1. Review the clean baseline. GitHub organization audit projection supplies the exercise evidence.
2. Consider the hypothesis. Repository-write token use on an unapproved runner should be correlated to workflow identity and job context.
3. Replay the positive fixture and inspect THX-32. Review runner pool, scope, workflow and actor. Match to an expected job and inspect resulting repository actions.
4. Compare the noisy fixture. A scheduled migration to a new runner pool can look anomalous before inventory catches up.

## Rule and evidence

Count at least 1 observation(s) per `user` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"automation_token_use"` |
| `outcome` | `eq` | `"success"` |
| `observables.runner_trust` | `eq` | `"unapproved"` |
| `observables.scope_class` | `eq` | `"repository_write"` |

Tuning guidance. Join runner identity and policy history. Review write permissions separately from read-only builds.

## Contain and prevent

Stop the affected workflow through approved controls, revoke the credential or session and review resulting changes.

Prefer short-lived workload identity and narrowly scoped job tokens. Require approved runner images and pools.

## Knowledge check

- Which permission raises the impact?
  - Repository write
  - The runner display name

<details>
<summary>Answer and rationale</summary>

Repository write. Write privileges can modify content or production configuration.

</details>

- What relationship supports the investigation?
  - The weekday of the event
  - Runner, workflow, job and repository actions

<details>
<summary>Answer and rationale</summary>

Runner, workflow, job and repository actions. A known job should explain the privilege and observed operation.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

The event contains no authentication material. It models suspicious use, not token acquisition.

Enterprise ATT&CK 20.1 · related. T1550.001 applies to use of an application access token. The sample does not show theft itself.
