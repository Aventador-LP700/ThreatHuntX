# 10 · WMI Subscription

Inspect a permanent WMI subscription binding and compare the owner and change context.

**Track** Intermediate · 12 min · Windows

**Prerequisites** Be comfortable reading timestamps and windows security or sysmon projection fields.

## Investigate

**Attacker intent** Event-triggered persistence.

**Learning outcome** Use Sysmon 21 to link filter and consumer. Check related filter and consumer records and authorized endpoint management changes.

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. A new permanent WMI binding with unknown ownership warrants a review of the filter, consumer and registration actor.
3. Replay the positive fixture and inspect THX-10. Use Sysmon 21 to link filter and consumer. Check related filter and consumer records and authorized endpoint management changes.
4. Compare the noisy fixture. Managed inventory software can register subscriptions during onboarding.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `event_id` | `eq` | `"21"` |
| `action` | `eq` | `"wmi_binding"` |
| `observables.namespace` | `eq` | `"root/subscription"` |
| `observables.owner_state` | `eq` | `"unknown"` |

Tuning guidance. Review specific inventory consumer names and signed owner identities before adding an exception.

## Contain and prevent

Preserve filter, consumer, binding and process telemetry. Remove confirmed unauthorized registrations with endpoint approval.

Collect WMI activity and monitor changes to permanent subscriptions on high-value hosts.
