# 12 · Credential dumping

Triage a Sysmon process access record involving the authentication subsystem.

**Track** Intermediate · 12 min · Windows

**Prerequisites** Be comfortable reading timestamps and windows security or sysmon projection fields.

## Investigate

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. Memory-read access to LSASS from an unverified caller warrants examination of the process and endpoint evidence.
3. Replay the positive fixture and inspect THX-12. Inspect source and target process, normalized access class and publisher. Check whether other records show suspicious output.
4. Compare the noisy fixture. Approved security tooling can legitimately inspect sensitive processes.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `event_id` | `eq` | `"10"` |
| `observables.target_process` | `eq` | `"lsass.exe"` |
| `observables.access_class` | `eq` | `"read_memory"` |
| `observables.publisher_status` | `eq` | `"unverified"` |

Tuning guidance. Use a verified publisher and deployed product identity for exceptions. Review vendor releases that change access behavior.

## Contain and prevent

Preserve endpoint evidence, isolate if supporting evidence exists and assess credential exposure before rotation.

Enable Credential Guard and LSASS protection where appropriate and audit their status.
