# 39 · RMM tool abuse

Review a remote-support session for a tool absent from the organization’s approved inventory.

**Track** Beginner · 8 min · Windows

**Prerequisites** Read the baseline and compare event fields. No external tools are required.

## Investigate

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. An external remote-support session using an unapproved tool should be matched to a valid support case.
3. Replay the positive fixture and inspect THX-39. Check the tool identity, origin, actor and support authorization. Correlate session and process activity.
4. Compare the noisy fixture. A current vendor support case may temporarily require a third-party tool.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"remote_support_session"` |
| `outcome` | `eq` | `"success"` |
| `observables.tool_approval` | `eq` | `"unapproved"` |
| `observables.peer_zone` | `eq` | `"external"` |

Review the following event-level exclusions before changing the rule.

- `observables.change_context` eq `"approved_support"`

Tuning guidance. Track temporary approvals by publisher, host and time. Remove unused remote tools from the inventory.

## Contain and prevent

Verify the support request, terminate unauthorized sessions and review activity performed during the session.

Allow approved support tools only, require MFA and maintain an inventory of remote-access agents.

## Knowledge check

- What should explain a legitimate session?
  - An approved support case tied to the tool and host
  - Any connection from an external IP

<details>
<summary>Answer and rationale</summary>

An approved support case tied to the tool and host. An approved case provides scope, owner and time.

</details>

- What helps verify actions during the session?
  - The application icon
  - Endpoint and session activity records

<details>

Endpoint and session activity records. Audit evidence can reveal what the operator did.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

The sample records only session metadata. The lab does not open a remote session or bundle a remote-access tool.
