# 31 · Malicious Dependencies

Investigate a dependency review that added a lifecycle hook and lost expected provenance.

**Track** Advanced · 15 min · CI/CD

**Prerequisites** Know the basics of CI/CD auditing and how to review authorization context.

## Investigate

**Attacker intent** Tamper with packages.

**Learning outcome** Compare lockfile diff, package identity, introduced hook metadata and publisher assertions.

1. Review the clean baseline. GitHub organization audit projection supplies the exercise evidence.
2. Consider the hypothesis. A new package version with an installation hook and missing provenance merits a review before approving a build.
3. Replay the positive fixture and inspect THX-31. Compare lockfile diff, package identity, introduced hook metadata and publisher assertions.
4. Compare the noisy fixture. A legitimate dependency may add build-time setup before enabling provenance.

## Contain and prevent

Pause the update, preserve the diff, verify upstream provenance and review existing builds for the version.

Use dependency review, pinned lockfiles, restricted install scripts and verified provenance.

## Knowledge check

- Which combination triggers review?
  - New install hook and missing provenance
  - Any change in lockfile line count

<details>
<summary>Answer and rationale</summary>

New install hook and missing provenance. Both behavior and provenance affect build trust.

</details>

- What should be inspected before approval?
  - Only the package logo
  - Package identity, source and lockfile diff

<details>
<summary>Answer and rationale</summary>

Package identity, source and lockfile diff. Review the precise version and its intended behavior.

</details>
