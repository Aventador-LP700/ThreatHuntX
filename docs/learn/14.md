# 14 · Pass-the-Hash

Review an NTLM network logon on a host that typically receives traffic from managed services.

**Track** Advanced · 15 min · AD

**Prerequisites** Know the basics of AD auditing and how to review authorization context.

## Investigate

**Attacker intent** Reused NTLM credentials.

**Learning outcome** Check package, logon type, peer zone and account class. Correlate authentication and process activity on both systems.

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. A successful NTLM network logon by a local administrator from a peer workstation warrants host-to-host review.
3. Replay the positive fixture and inspect THX-14. Check package, logon type, peer zone and account class. Correlate authentication and process activity on both systems.
4. Compare the noisy fixture. An approved help-desk task can use legacy authentication between systems.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

Tuning guidance. Identify approved jump hosts and prefer central, constrained administration over broad user exclusions.

## Contain and prevent

Scope the source and destination, preserve access logs, and reset impacted local administrator credentials if appropriate.

Roll out unique managed local administrator passwords, restrict NTLM and segment administration traffic.

## Knowledge check

- What indicates the network logon?
  - Logon type 3 in event 4624
  - A file rename

<details>
<summary>Answer and rationale</summary>

Logon type 3 in event 4624. Event 4624 establishes success and type 3 indicates a network logon.

</details>

- What should an analyst correlate?
  - The account spelling alone
  - Both source and destination endpoint activity

<details>
<summary>Answer and rationale</summary>

Both source and destination endpoint activity. A lateral movement assessment needs evidence across systems.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

NTLM logon metadata alone cannot distinguish a password from another form of authentication material.

Enterprise ATT&CK 20.1 · related. An anomalous NTLM logon is compatible with pass-the-hash, but the authentication record does not identify credential form.
