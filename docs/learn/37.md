# 37 · Cloud metadata theft

Find a network classification showing an unexpected workload requesting the cloud metadata credential service.

**Track** Advanced · 15 min · Cloud

**Prerequisites** Know the basics of Cloud auditing and how to review authorization context.

## Investigate

1. Review the clean baseline. Network sensor or WAF projection supplies the exercise evidence.
2. Consider the hypothesis. A metadata credential request by an unapproved workload warrants checking workload identity and access policy.
3. Replay the positive fixture and inspect THX-37. Read the caller classification and verdict, then pivot to cloud audit for any follow-on role activity.
4. Compare the noisy fixture. A deployed agent or SDK may require metadata access to obtain authorized role credentials.

## Rule and evidence

Count at least 1 observation(s) per `user` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"metadata_request"` |
| `observables.request_class` | `eq` | `"instance_credentials"` |
| `observables.caller_class` | `eq` | `"unexpected_workload"` |

Tuning guidance. Map approved workloads and separate credential requests from benign metadata classes.

## Contain and prevent

Preserve application and network records, scope workload identity and remove unauthorized permission or access.

Require IMDSv2 where supported, constrain metadata access and limit instance-role privileges.

## Knowledge check

- Which context matters beyond metadata access?
  - What was requested and which workload made the request
  - The URL text color

<details>
<summary>Answer and rationale</summary>

What was requested and which workload made the request. Authorized agents make some requests. Caller and request type add context.

</details>

- Which source helps determine if a role was used afterward?
  - Only the WAF signature name
  - Cloud audit records

<details>
<summary>Answer and rationale</summary>

Cloud audit records. Cloud audit can show subsequent API activity by the role.

</details>

## Validation and mapping
