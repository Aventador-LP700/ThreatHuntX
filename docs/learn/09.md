# 09 · Registry Autoruns

Distinguish an unexpected Windows logon autorun change from an approved application update.

**Track** Beginner · 8 min · Windows

**Prerequisites** Read the baseline and compare event fields. No external tools are required.

## Investigate

**Attacker intent** Unexpected logon persistence.

**Learning outcome** Read Target Object and writer process provenance. Confirm the configured path and trace the associated logon or process events.

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. A Run or RunOnce value written by a process of user-writable origin requires checking the executable and autorun target.
3. Replay the positive fixture and inspect THX-09. Read Target Object and writer process provenance. Confirm the configured path and trace the associated logon or process events.
4. Compare the noisy fixture. Legitimate per-user installers can add logon entries outside centrally managed application paths.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `event_id` | `eq` | `"13"` |
| `action` | `eq` | `"registry_value_set"` |
| `observables.registry_area` | `in` | `["run", "run_once"]` |
| `observables.image_origin` | `eq` | `"user_writable"` |

Review the following event-level exclusions before changing the rule.

- `observables.approved_change` eq `true`

Tuning guidance. Verify publisher and installation context. A blanket exception for user-writable paths removes a useful signal.

## Contain and prevent

Preserve registry and process evidence. Remove an unauthorized value with endpoint team approval, and look for related sign-ins.

Keep a software and autorun baseline, restrict execution from user-writable paths and monitor registry change events.

## Knowledge check

- Which record type indicates the value was set?
  - Sysmon Event ID 13
  - A DNS response

<details>
<summary>Answer and rationale</summary>

Sysmon Event ID 13. Sysmon 13 is a registry value set. The target field names the location.

</details>

- What should you verify before allowing the change?
  - Just whether the file name ends in .exe
  - Writer publisher and expected installation scope

<details>
<summary>Answer and rationale</summary>

Writer publisher and expected installation scope. Endings are common across benign and suspicious binaries.

</details>
