# 17 · LOLBins/LOLBAS

Triage a signed Windows binary invoked by an unusual parent and directed at an untrusted content location.

**Track** Intermediate · 12 min · Windows

**Prerequisites** Be comfortable reading timestamps and windows security or sysmon projection fields.

## Investigate

**Attacker intent** Abuse trusted system tools.

**Learning outcome** Inspect parent, path provenance and signer. Review any related child process and connection events.

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. A signed proxy binary launched by an office parent with user-writable content warrants process-chain review.
3. Replay the positive fixture and inspect THX-17. Inspect parent, path provenance and signer. Review any related child process and connection events.
4. Compare the noisy fixture. A legacy business application can invoke these Windows binaries from Office automation.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `event_id` | `eq` | `"1"` |
| `process` | `in` | `["rundll32.exe", "regsvr32.exe"]` |
| `parent_process` | `in` | `["winword.exe", "outlook.exe"]` |
| `observables.content_origin` | `eq` | `"user_writable"` |

Tuning guidance. Constrain an exception to an approved process chain and module path, with review when either changes.

Preserve lineage and metadata. Scope unintended effects before isolating the endpoint.

Use application control and audit document applications that launch child processes.

## Knowledge check

- Why does the signed executable still deserve review?
  - Its parent and content provenance are unusual
  - A signature means it is always unauthorized

<details>
<summary>Answer and rationale</summary>

Its parent and content provenance are unusual. Context distinguishes trustworthy software from unsafe use of it.

</details>

- What should tuning preserve?
  - An exception for all signed binaries
  - Visibility of unapproved parent and content combinations

<details>
<summary>Answer and rationale</summary>

Visibility of unapproved parent and content combinations. Broad trust loses the relationship the rule relies on.

</details>
