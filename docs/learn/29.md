# 29 · Infostealers

Look for unexpected reads of a browser credential-store category by a process without established trust.

**Track** Advanced · 15 min · Windows

**Prerequisites** Know the basics of Windows auditing and how to review authorization context.

## Investigate

**Attacker intent** Harvest browser secrets.

**Learning outcome** Compare credential-store classification, actor image, trust and related process or network observations.

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. An unapproved non-browser reader accessing credential storage should be correlated with process provenance and account risk.
3. Replay the positive fixture and inspect THX-29. Compare credential-store classification, actor image, trust and related process or network observations.
4. Compare the noisy fixture. A sanctioned migration or endpoint backup could read profile storage.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"file_access"` |
| `observables.target_type` | `eq` | `"browser_credential_store"` |
| `observables.actor_type` | `eq` | `"unapproved_nonbrowser"` |
| `observables.operation` | `eq` | `"read"` |

Review the following event-level exclusions before changing the rule.

- `observables.migration_approved` eq `true`

Tuning guidance. Tune by verified publisher and reviewed operation. Keep exceptions distinct from browser session-store access.

## Contain and prevent

Isolate an affected endpoint if corroborated, identify exposed accounts and rotate credentials through approved policy.

Apply endpoint hardening, managed browser policy and monitored credential-store access.

## Knowledge check

- Which store is relevant?
  - Browser credential storage
  - The browser cache alone

<details>
<summary>Answer and rationale</summary>

Browser credential storage. Credential-store access and session-cookie access are different observations.

</details>

- What evidence assists scoping?
  - A single resolution timestamp
  - Related process, endpoint and account events

<details>
<summary>Answer and rationale</summary>

Related process, endpoint and account events. Additional telemetry helps determine whether access led to credential use.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

No secret value or profile database is present. The access record does not show successful credential decryption.
