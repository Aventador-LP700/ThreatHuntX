# 18 · Security tool tampering

Review a defensive tool state change and determine whether it is supported by a change record.

**Track** Intermediate · 12 min · Windows

**Prerequisites** Be comfortable reading timestamps and windows security or sysmon projection fields.

## Investigate

1. Review the clean baseline. Windows security or Sysmon projection supplies the exercise evidence.
2. Consider the hypothesis. An unexpected stopped state for an endpoint protection service warrants checking management heartbeat and actor.
3. Replay the positive fixture and inspect THX-18. Check the service, new state, surrounding activity, managed heartbeat and any maintenance authorization.
4. Compare the noisy fixture. An approved upgrade can temporarily stop an agent.

## Rule and evidence

Count at least 1 observation(s) per `host` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `event_id` | `eq` | `"7036"` |
| `observables.service_class` | `eq` | `"endpoint_protection"` |
| `observables.new_state` | `eq` | `"stopped"` |

Review the following event-level exclusions before changing the rule.

- `observables.change_context` eq `"approved_upgrade"`

Tuning guidance. Treat the maintenance window as expiring context, and check for restart and protection recovery.

## Contain and prevent

Preserve logs, verify endpoint health from a separate source and restore protection through approved administration.

Enable tamper protection and retain service and security logs off the endpoint.

## Knowledge check

- Which corroboration helps assess impact?
  - Agent heartbeat or management status
  - The taskbar layout

<details>
<summary>Answer and rationale</summary>

Agent heartbeat or management status. An independent health source helps verify the service outage and eventual recovery.

</details>

- When should a maintenance exception expire?
  - Whenever the first alert is closed
  - When the approved change ends

<details>
<summary>Answer and rationale</summary>

When the approved change ends. An expiring exception keeps visibility of unexpected outages.

</details>

## Validation and mapping

Baseline and noisy fixture produce no alerts. The positive fixture produces an alert with linked evidence.

The fixture records a state transition. It does not exercise tamper behavior or prove deliberate defense impairment.

Enterprise ATT&CK 20.1 · direct. The behavior in this lesson corresponds to this technique; the fixture models a defensive observation.
