# 08 · Scheduled Tasks/Cron

Review a synthetic cron modification and compare a user-managed schedule with approved deployment automation.

**Track** Beginner · 8 min · Linux

**Prerequisites** Read the baseline and compare event fields. No external tools are required.

## Investigate

**Attacker intent** Recurring malicious startup.

**Learning outcome** Find the writer, schedule owner, file path and change window. Compare the review record for the host.

1. Review the clean baseline. Linux audit projection supplies the exercise evidence.
2. Consider the hypothesis. A root-owned cron change originating from an interactive write is worth checking against change management.
3. Replay the positive fixture and inspect THX-08. Find the writer, schedule owner, file path and change window. Compare the review record for the host.
4. Compare the noisy fixture. An administrator may create a job during approved maintenance.

## Rule and evidence

Count at least 1 observation(s) per `user` inside 300 seconds. Each distinct source record can count once.

| Field | Comparison | Value |
| --- | --- | --- |
| `action` | `eq` | `"cron_change"` |
| `observables.schedule_owner` | `eq` | `"root"` |
| `observables.origin_class` | `eq` | `"user_write"` |

Tuning guidance. Join known deployment identities and documented change windows. Keep unexpected schedule owners visible.

## Contain and prevent

Preserve the audit trail and job definition, verify the owner, then remove an unauthorized entry according to policy.

Restrict cron directory writes and monitor job definitions and changes.

## Knowledge check

- Whose schedule was changed?
  - Root
  - The package registry

<details>
<summary>Answer and rationale</summary>

Root. The schedule owner and the actor are distinct fields.

</details>

- What can explain the change?
  - Any timestamp during business hours
  - A verified maintenance record with matching scope

<details>
<summary>Answer and rationale</summary>

A verified maintenance record with matching scope. Authorization requires a change record, accountable actor and matching host.

</details>
